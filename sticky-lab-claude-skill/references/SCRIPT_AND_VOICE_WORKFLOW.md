# Script and Voiceover Workflow

## A. Script diagnosis
Before designing scenes, label the script beats:
1. Hook / curiosity trigger
2. Main claim or question
3. Explanation beat(s)
4. Example, analogy, or contrast
5. Payoff / summary / call to action

Do not force all five beats into a very short video. For a 15-second explainer, use 3–5 visual beats and keep each beat focused.

## B. Preserve meaning
- Do not rewrite the user's words unless asked.
- If the script is too long for the requested duration, estimate the required speaking pace and explain the conflict. Offer a tightened version only when useful; do not silently cut meaning.
- Keep on-screen copy shorter than the narration. Do not transcribe the entire voiceover onto the screen.
- A visual metaphor should support the line being spoken at that moment.

## C. Voiceover cases
### Case 1: Audio file supplied
- Establish actual duration from file metadata or audio analysis if tools are available.
- Use waveform, transcription, forced alignment, or speech recognition if available.
- Mark timestamps as measured only if actually measured.
- Place visual events at meaningful phrases, pauses, and emphasis.
- Preserve the supplied audio. Do not generate a replacement voice unless asked.
- If the final phrase ends before the video, use a purposeful visual hold or end card rather than accidental silence.

### Case 2: Text only
- Estimate speech duration based on the language and delivery style.
- Use a clear conversational Arabic pace by default; adjust for dialect, emphasis, and pauses.
- Label the timing “estimated” and avoid fake precision.
- Put the full narration text in a VO column and concise screen text in a separate column.

### Case 3: Script and audio both supplied
- Audio duration and actual spoken content are authoritative for synchronization.
- Compare script to audio where possible.
- Flag omitted, added, or changed wording.
- Do not squeeze the visuals to a timing grid that contradicts the actual spoken delivery.

## D. Scene map format
Use a table with:
- Scene ID
- Start/end time and duration
- Voiceover phrase
- Story beat / purpose
- Main visual metaphor
- On-screen text (exact)
- Assets needed
- Animation and transition
- Sound cue
- Timing confidence: measured / estimated

## E. Timing principles
- A scene should change when the idea changes, not simply every fixed number of seconds.
- For 15 seconds, typically plan 3–5 scenes; use fewer if narration is dense.
- Hook should be visually clear in the first 1–2 seconds.
- Avoid cutting faster than viewers can read.
- Reveal keywords on emphasis words; keep secondary annotations brief.
- Do not claim word-level synchronization unless alignment has been performed.
